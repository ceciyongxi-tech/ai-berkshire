# AI基础设施CapEx同源风险研究报告

> **研究日期：** 2026-07-28  
> **数据截止：** 2026-07-28 JST；美股公司价格信息如有涉及，以 2026-07-27 收盘为准  
> **研究范围：** 全球 AI 基础设施产业链，重点分析收入对同一批 AI 资本开支预算的依赖、风险传导、结构性回避标的与避险方向  
> **核心口径：** Microsoft、Alphabet、Amazon、Meta 的 2026 年公司级 CapEx 指引合计约 **7,100 亿—7,400 亿美元**，中点 **7,250 亿美元**；该数字不是纯 AI CapEx，也不能与 Oracle、CoreWeave 的 CapEx、云合同、RPO 或供应商收入重复相加  
> **一句话判断：** AI 基建看似由 GPU、HBM、光模块、服务器、液冷、电力和数据中心等多个行业组成，实质上却是少数预算委员会控制的一笔资本开支在多层会计主体中的重复确认；真正的风险控制不是持有更多产业链股票，而是降低对这一共同预算因子的总暴露。

## AI研究偏见自觉

### 信息充分度

| 项目 | 评级 | 说明 |
|---|---|---|
| 四大云厂商 CapEx | A | 公司已披露季度实际值与年度指引，可由公司 IR、SEC 和权威媒体交叉核验 |
| 上市供应商客户集中度 | A-/B+ | 10-K、20-F 披露较充分，但部分客户匿名，无法总是确认最终预算主体 |
| OpenAI、Anthropic、xAI 现金流 | C | 私营公司披露不完整，融资承诺、实际到账和采购义务口径不同 |
| neocloud 合同质量 | B | 可看到 backlog、RPO、债务和部分合同，但取消、重谈与追索条款并不完全公开 |
| 个股当前估值 | B | 价格变化快，且本报告目标是因子风险而非逐家公司估值 |

### 共识陷阱

1. **文明趋势正确，不代表建设者都能赚钱。** AI 需求长期增长与资本回报率达标是两个问题。
2. **订单增长，不等于终端需求分散。** ODM、云商和 neocloud 可以让直接客户名单变长，却不改变最终预算来源。
3. **backlog 不等于现金。** RPO、云承诺和订单跨越不同年限，可能含预付款、自带 GPU、融资条款或重新谈判空间。
4. **好公司不等于好对冲。** NVIDIA、TSMC、Arista、Vertiv 可以是好公司，但都不是 AI CapEx 下行的避险资产。
5. **电力并非天然避险。** 当核电、变压器、液冷、铜和数据中心 REIT 的增长预期同样依赖数据中心建设时，它们只是同一预算的后端表达。

### 本报告最可能犯的错误

最可能的错误是低估推理需求的价格弹性：即使单位 token 成本快速下降，使用量可能增长得更快，使过剩产能比历史电信周期更快被消化。反过来，最危险的错误则是把“需求最终会来”误当成“今天的建设成本、融资结构和股票价格都合理”。

## 第二步：同一预算如何穿透产业链

### 经济链条

```text
广告 / 企业软件 / 电商 / 传统云现金流
                ↓
    Microsoft / Alphabet / Amazon / Meta
                ↓ 投资、授信、云合同
       OpenAI / Anthropic / xAI
                ↓ 算力采购承诺
 Azure / AWS / Google Cloud / OCI / 第三方云
                ↓ 预付款、合同抵押、租赁
       CoreWeave / neocloud / 项目公司
                ↓ 设备采购
 GPU → HBM → 晶圆与封装 → 网络与光模块
     → 服务器与机柜 → UPS/液冷/配电 → 数据中心
```

### 五类不能相加的数字

1. OpenAI、xAI 等模型公司的融资额；
2. 模型公司承诺的云消费合同；
3. 云商记录的 RPO 或 backlog；
4. Oracle、CoreWeave 等中间平台的 CapEx；
5. NVIDIA、服务器、网络、光模块和电力设备商确认的收入。

这些数字处于同一笔经济活动的不同阶段。典型例子是：

```text
云商或芯片商投资模型公司
    → 模型公司承诺购买云算力
        → 云商将承诺计入 RPO 并扩 CapEx
            → 中间云用合同和 GPU 抵押融资
                → 向同一芯片商采购
```

直接客户可能从一家变成五家，但最终付款能力仍取决于少数广告、软件、云和融资现金流。

### 真正的终端预算来源

| 来源 | 当前可靠性 | 主要风险 |
|---|---|---|
| 广告现金流 | 高 | 宏观衰退、监管、AI 搜索改变广告变现 |
| 企业软件与传统云 | 高 | 客户优化支出、AI 产品蚕食原有软件席位 |
| 电商与履约现金流 | 中高 | Amazon CapEx 同时覆盖多条非 AI 业务 |
| AI API、订阅、广告增量 | 中 | 当前收入规模能否覆盖巨额算力承诺尚待验证 |
| 股权、债务和预付款融资 | 中低 | 利率、信用利差、估值和投资者风险偏好变化 |
| 主权 AI 和企业自建 | 中 | 预算相对分散，但规模、回报和政策持续性不确定 |

## 第四步：逆向思考与风险清单

### 最强反方观点

> 这轮 AI 基建并不是十几个独立客户同时验证了需求，而是少数现金牛公司、模型公司和融资平台互相投资、互相签合同、再用合同融资扩建。供应链收入增长是真实的，但独立终端付款能力并没有收入表面显示的那么分散。只要最终 AI 变现、融资条件或建设节奏中有一项不及预期，合同、GPU 残值、贷款抵押物和上游订单会同时恶化。

### 主要失败路径

| 风险 | 概率判断 | 影响 | 传导路径 | 可观察指标 |
|---|---|---|---|---|
| 四大预算增速下调 | 中 | 极高 | 云厂商 → GPU/服务器 → HBM/光模块 → 电力设备 | 合计 CapEx 指引下调幅度 |
| OpenAI/xAI 融资或付款延迟 | 中 | 极高 | 模型公司 → Oracle/CoreWeave/AWS/Azure → 供应商 | 融资实际到账、合同重谈、预付款 |
| AI 单位经济性不达标 | 中 | 极高 | API/订阅收入不足 → ROIC 下滑 → CapEx 审查 | AI 收入、Cloud 毛利、折旧增长 |
| 自研 ASIC 替代通用 GPU | 高 | 公司分化大 | 总 CapEx 不降，但 NVIDIA/相关 HBM/网络份额变化 | TPU、Trainium、MTIA、定制 ASIC 部署 |
| 组件涨价掩盖采购量放缓 | 高 | 中高 | CapEx 上升但芯片、机柜单位数不等幅增长 | CapEx 中价格与数量拆分 |
| 电力、并网、许可延期 | 高 | 中高 | GPU 到货但数据中心无法通电，折旧先于收入 | energized GW，而非 announced GW |
| 库存与采购承诺反噬 | 中 | 高 | 最终需求小幅下降被供应链牛鞭放大 | 库存增速、不可取消采购/收入 |
| 技术淘汰快于折旧 | 中 | 高 | 旧 GPU 租价和抵押价值下跌 | 云租价、利用率、二手 GPU 残值 |
| 利率或信用利差上升 | 中 | 高 | neocloud、项目公司和 Oracle 融资成本上升 | 债券利差、贷款条款、股权融资 |

### 价格上涨不等于数量增长

Microsoft 明确表示 2026 年约 1,900 亿美元 CapEx 中，约 250 亿美元来自组件价格上涨；Meta 上调指引也主要归因于组件定价，其次才是新增数据中心成本。因此 CapEx 指引上调不能直接推导 GPU、光模块或服务器数量同比等幅增长。

### backlog 质量错觉

Microsoft、Oracle、CoreWeave 均披露了巨额 RPO 或 backlog，但三者存在：

- 期限不同；
- 同一终端客户重复出现；
- 客户预付或自带硬件；
- 合同融资与租赁；
- 取消、延期、重谈和信用风险。

正确的分析不是比较 backlog 总额，而是看：

1. 未来 12—24 个月转换比例；
2. 剔除 OpenAI、Meta 等大客户后的增长；
3. 预付款和追索权；
4. 资本开支与合同收入的时间匹配；
5. 客户信用与供应商融资占比。

## 第五步：结构性回避标的

### 第一类：优先回避

| 公司/商业模式 | 回避理由 | 需要什么变化才可重审 |
|---|---|---|
| CoreWeave | 客户集中、高负债、高利息、GPU 抵押融资、CapEx 远超经营现金流；需求、信用、残值和再融资风险叠加 | 客户集中显著下降；FCF 转正；债务/EBITDA 和利息覆盖明显改善 |
| Wiwynn | 前三客户约占 96%，毛利率低，定制化强，几乎没有终端预算多元化 | 客户结构真正分散；服务/软件收入提高；采购与库存风险下降 |
| Supermicro | 四个 10% 以上客户、低毛利整机、长交期部件、平台快速换代 | 毛利和现金转换改善；集中度下降；库存增速低于收入 |
| 高杠杆 neocloud/矿场转型项目 | 用短历史、单一租户和高杠杆建设长寿命资产 | 长期不可撤销合同、强担保、低杠杆和已通电利用率得到验证 |

### 第二类：仅适合周期交易，不宜作为核心仓位

| 环节/公司 | 主要原因 |
|---|---|
| Coherent、Lumentum 等光器件纯标的 | 客户少、固定制造成本高、技术路线切换快 |
| Micron、SK hynix 等 HBM 强周期暴露 | 锁量不等于长期锁价；扩产兑现可能与需求降速重叠 |
| Arista | 生意质量高，但客户集中和采购承诺结构不防御 |
| Vertiv | backlog 强，但如果估值把异常订单速度永久化，赔率会迅速恶化 |
| Dell AI 服务器业务 | 集团较分散，但 AI 服务器仍是低毛利 GPU pass-through |

### 第三类：好公司，但不能作为对冲

- NVIDIA；
- TSMC；
- Broadcom；
- Eaton；
- Schneider Electric；
- Equinix；
- Digital Realty；
- 电力和核电运营商。

这些公司的经营质量、客户合同和资产负债表可能优于纯供应链公司，但股价和盈利仍不同程度依赖 AI 数据中心建设。持有更多产业链环节，不会自动降低共同 CapEx 因子。

## 第六步：可以降低风险的行业与公司

### 真正的资本保护

股票中几乎没有对 AI CapEx 下行保持稳定负相关的公司。最可靠的资本保护仍是：

1. 现金；
2. 短久期国债；
3. 指数或供应链个股的保护性期权；
4. 降低主题总仓位，而不是寻找另一个 AI 标签。

### 更接近经营对冲的上市公司

| 类型 | 公司 | 对冲机制 | 主要反证 |
|---|---|---|---|
| 交易所 | CBOE、CME | 市场冲击和不确定性可能提高衍生品交易量 | 温和降速而非市场冲击时，交易量可能恢复常态 |
| 重组咨询 | FTI Consulting | 信用收缩、违约、重组和诉讼需求增加 | 人力成本高，交易咨询可能同步放缓 |
| 流动性选择权 | Berkshire Hathaway | 大量现金和短期美债，可在资产下跌后重新配置 | 股价不是稳定负相关，铁路和制造仍有周期 |
| 财产险 | Chubb | 保费、承保利润和投资收益不直接依赖 AI CapEx | 巨灾、责任险周期、资产价格波动 |
| 必需服务 | Waste Management、Waste Connections | 垃圾收运、填埋、路线密度和长期合同 | 工业垃圾量仍受经济周期影响，估值可能偏高 |

CME 2025 年总合约量和清算交易费均约 +6%，产品横跨利率、股指、能源、外汇、农产品和金属；Chubb 2025 年净保费 +6.6%，综合成本率 85.7%；Waste Management 约 30% 收入来自剩余期限超过一年的合同。来源：[CME 2025 10-K](https://www.sec.gov/Archives/edgar/data/1156375/000115637526000009/cme-20251231.htm)、[Chubb 2025 10-K](https://www.sec.gov/Archives/edgar/data/896159/000089615926000005/cb-20251231.htm)、[Waste Management 2025 10-K](https://www.sec.gov/Archives/edgar/data/823768/000110465926012049/wm-20251231x10k.htm)。

### 低相关、资产轻和算力降价受益者

| 公司类型 | 观察标的 | 为什么可能受益 | 为什么不是真对冲 |
|---|---|---|---|
| 创意与文档软件 | Adobe | 算力价格下降有利于降低 AI 功能单位成本 | 生成式 AI 可能直接削弱原有护城河 |
| 财税软件 | Intuit | 订阅收入、低实物 CapEx，可将 AI 用于自动化 | AI 代理也可能压低报税和记账价格 |
| 支付网络 | Visa | 收入由支付量和跨境交易驱动，而非数据中心 CapEx | 若 CapEx 崩塌伴随衰退，支付量也会下降 |
| 企业软件 | Salesforce、ServiceNow | 资产轻、订阅型，可能受益于更便宜的算力 | 更直接依赖企业 AI/数字化预算，不宜当 hedge |

### AI 链内相对稳健

```text
Equinix 核心互联与零售 colocation
    > Eaton ≈ Schneider Electric
    > Digital Realty 已签长期租约资产
    > Samsung 集团 / Broadcom 软件缓冲
    > TSMC / ASE
    > NVIDIA / Vertiv / Dell
    > Arista / HBM纯标的 / 光器件
    > Supermicro / Wiwynn / 高杠杆neocloud
```

这里的“稳健”只表示经营抗冲击能力较强，不代表股价在 AI CapEx 下调时会上涨。

### 伪避险清单

以下行业往往只是把同一笔预算换了一个标签：

- 数据中心核电和独立电力生产商；
- 变压器、UPS、液冷、配电设备；
- 铜、铀、天然气等 AI 电力叙事；
- 数据中心 REIT；
- 数据中心建筑和工程承包商；
- 由加密货币矿场转型的 AI 机房开发商。

已签长期 PPA 或租约可以保护局部现金流，却不能消除新增增长、估值和续约对下一批 AI 数据中心项目的依赖。

## 第七步：历史类比与估值纪律

### 1998—2002 年电信与光纤建设潮

最接近的历史类比不是普通半导体库存周期，而是电信和光纤建设：

1. 互联网长期需求判断正确；
2. 多家公司同时按自己将取得巨大终局份额进行建设；
3. 融资条件收紧和需求预期下降后，设备、组件和高杠杆运营商先受伤；
4. 过剩基础设施多年后降低了应用公司的使用成本；
5. 最终技术受益者与早期资本提供者并不相同。

Cisco FY2001 因需求突然显著下降，对库存及采购承诺计提约 27.7 亿美元拨备。美联储当时也指出，资本开支回落首先传导至电信设备和其他高科技资本品制造商。来源：[Cisco 2001 Annual Report](https://www.cisco.com/c/dam/en_us/about/ac49/ac20/downloads/annualreport/ar2001/pdf/AR.pdf)、[Federal Reserve: Reflections on the capital goods overhang](https://www.federalreserve.gov/boarddocs/speeches/2001/20010718/default.htm)。

### 2022—2023 年云优化周期

AWS 曾允许客户退回容量并帮助客户优化支出；Microsoft 也观察到 Azure 客户优化既有工作负载。说明云收入不是不可逆的固定租金：当客户从抢容量转向算 ROI，使用量和新采购可以迅速减速。

### 半导体库存周期

Micron FY2023 收入由 FY2022 的 307.6 亿美元降至 155.4 亿美元，约 -49%；毛利率由约 45% 降至 -9%，并出现大额库存可变现净值减记。文明趋势、数据增长和长期存储需求均未被证伪，但固定成本、库存和价格周期仍然摧毁了短期利润。

### 估值纪律

本报告不为每家公司给出目标价，因为研究目标是共同因子风险。对 AI 基建股票，估值至少应回答：

1. 当前价格隐含未来几年 CapEx 增长多少？
2. 隐含毛利率是否把短缺定价永久化？
3. backlog 是否被当作无信用风险的现金？
4. 如果收入不增长，仅靠现有利润和股东回报，估值是否仍可接受？
5. 如果客户自研芯片或替代供应商成功，公司价值还剩多少？
6. 当前买入是否是在支付“所有大厂都按计划建设、所有合同都兑现、融资永远开放”的完美价格？

## 第八步：最终决策与行动清单

### 行业总评

| 维度 | 结论 | 信心度 |
|---|---|---|
| AI 文明趋势 | 长期成立，推理、代理和模型应用仍可能持续扩大 | 高 |
| CapEx 独立性 | 低，最终预算和融资来源高度集中 | 高 |
| 收入重复计算风险 | 高，融资、云合同、RPO、CapEx 与供应链收入相互重叠 | 高 |
| 最佳经营环节 | 平台型芯片、先进制造、分散托管和多元电气平台 | 中高 |
| 最大风险环节 | 高杠杆 neocloud、低毛利 ODM、光器件纯标的、HBM 周期纯暴露 | 高 |
| 真正避险资产 | 现金、短债、保护性期权；股票只能提供经营低相关或事件受益 | 高 |
| 当前投资策略 | 降低共同因子暴露，避免把产业链多标的误当分散 | 高 |

### 空仓投资者

| 动作 | 条件 |
|---|---|
| 暂不参与高杠杆中间层 | CoreWeave、单一租户项目和矿场转型数据中心的 FCF、债务和客户集中尚未改善 |
| 只研究高质量平台 | 优先看资产负债表、客户分散、软件/服务缓冲和定价权 |
| 等待周期信号 | CapEx 数量增长、已通电容量、AI 收入和 FCF 同时得到验证 |
| 估值留安全边际 | 不为 backlog、规划 GW 或短缺毛利率支付永久化价格 |

### 已持有 AI 基建股票的投资者

首先把以下仓位合并成一个共同风险桶：

```text
NVIDIA + AMD + HBM + Arista + 光模块 + 服务器
+ Vertiv/液冷 + 电力设备 + 数据中心 REIT + AI电力
```

这些并不是十个独立仓位，而是对同一批预算的不同敏感度。

对偏保守的组合，可考虑把直接 AI 基建纯标的合计控制在总组合的 **10%—15%以内**；高杠杆 neocloud 应更低或直接回避。该上限是风险预算建议，不是对任何个股的目标仓位。

### 加仓、减仓与退出信号

| 信号 | 具体条件 |
|---|---|
| 加仓信号 | 四大 CapEx 指引维持，但 OCF/CapEx 与 FCF 开始改善；AI 收入和 Cloud 毛利增速高于折旧；供应商库存增速低于收入；已通电容量按计划转化为收入 |
| 减仓信号 | 四大合计 CapEx 指引下调超过 10%；两个以上供应商 book-to-bill 低于 1；库存连续两个季度快于收入；组件涨价贡献大于采购数量增长 |
| 高风险退出信号 | 大额云合同重谈或融资延期；neocloud 信用利差快速扩大；GPU 云租价、利用率和二手残值同步下跌；客户预付款停止增长且债务继续上升 |
| 论文重审信号 | 自研 ASIC 份额显著变化；模型效率使训练/推理计算需求结构改变；监管或出口限制改变可服务市场 |

### 最终排序

```text
资本保护：
现金 / 短债 / 保护性期权
    >
经营对冲：
CBOE / CME / FTI Consulting / Berkshire Hathaway
    >
低相关防御：
保险 / 垃圾处理 / 部分资产轻应用
    >
AI链内相对稳健：
Equinix / Eaton / Schneider / Broadcom / TSMC
    >
高同因子暴露：
NVIDIA / HBM / Arista / Vertiv / 光模块 / 服务器
    >
结构性高风险：
CoreWeave / Wiwynn / 高杠杆neocloud
```

> **段永平式问题：** 如果 AI CapEx 明年不增长，这家公司还能不能靠客户、现金流和商业模式活得很好？  
> **巴菲特式问题：** 护城河保护的是利润，还是只保护了订单份额，却保护不了资本回报率？  
> **芒格式问题：** 哪家公司同时承担了客户集中、库存、技术淘汰、杠杆和再融资五种风险？  
> **李录式问题：** AI 是文明趋势，但谁在以合理成本拥有真正可持续的价值，而不是替全行业承担建设风险？

## AI分析置信度 vs 投资确定性

| 项目 | 置信度 |
|---|---|
| 四大公司级 CapEx 合计与现金流压力 | 高 |
| 产业链收入存在重复计算 | 高 |
| CoreWeave、Wiwynn、SMCI 风险结构较差 | 高 |
| NVIDIA、TSMC 等高质量公司不是 CapEx 对冲 | 高 |
| CME、CBOE、FTI、Berkshire 经营相关性较低 | 中高 |
| AI 应用公司会直接受益于算力过剩 | 中 |
| AI CapEx 周期顶部的准确时间 | 低 |
| 各公司当前价格的预期回报 | 未在本报告逐一估值，不能据此判断 |

研究数据的可靠性不等于投资结果的确定性。即使 CapEx 集中度判断正确，股价仍可能因盈利超预期、供给短缺持续、利率变化或市场风险偏好而长期偏离基本面风险。
