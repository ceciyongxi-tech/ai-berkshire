# CPU 与 GPU：推理时代投资研究报告

> **研究日期**：2026-07-29（JST）  
> **市场数据截止**：2026-07-28 美股盘中约 10:00–11:00 ET，价格仍在变动  
> **研究问题**：“未来推理大于训练”是否合理？如果合理，CPU 是否因此成为更好的投资方向，具体标的是谁？  
> **一句话结论**：推理在 token 量、调用次数和运行时长上超过训练是高概率事件，但这并不等于 CPU 会替代 GPU；大模型核心 token 生成仍由 GPU/ASIC 主导，CPU 的增量来自宿主、编排、RAG、数据库和工具执行。若只看业务，AMD 是最强直接 CPU 标的；若看风险调整后收益，TSMC 更优；按当前价格，四个主要候选均不具备宽安全边际。

本报告用于学习与研究，不构成投资建议。

| 项目 | 判断 |
|---|---|

## 第一步：先定义“推理大于训练”

### 五种口径，只有部分已经成立

| 口径 | 当前证据 | 结论 | 置信度 |
|---|---|---|---|
| 推理 token / 调用量 | Alphabet 披露跨产品月处理 token 从 2025 年 5 月的 480 万亿增至 7 月的 980 万亿；Microsoft Foundry 单季处理 100 万亿 token、同比约 5 倍 | 已经非常大，未来显著超过训练 token 高度合理 | 高 |
| 总 FLOPs | Epoch AI 估计大型开发者约 60%–80% 计算分配给推理，但训练和推理仍处同一数量级 | “略大于”合理，“压倒训练”证据不足 | 中 |
| 年度能耗 | IEA 汇总的历史 ML 车队数据约 60%–70% 能耗来自推理、20%–40% 来自训练 | 很可能已超过，但广义 ML 不等于纯生成式 AI | 中高 |
| 芯片收入 | GPU、TPU、ASIC 同时服务训练和推理，供应商不拆分收入 | 不能验证推理芯片收入已过半 | 低 |
| 服务器 CapEx | 云厂商披露总机器/服务器投资，不拆训练与推理 | 不能验证推理 CapEx 已过半 | 低 |

关键证据：

- Epoch AI 的 2030 情景认为推理目前可能占主要开发者计算的 60%–80%，但也认为训练和推理都可能高速扩张，不能把它解读成训练消失。[Epoch AI《AI in 2030》](https://epoch.ai/files/AI_2030.pdf)
- Gartner 预计 2026 年 55% 的 AI 优化 IaaS 支出将支持推理，但其点名的硬件仍是 GPU、TPU 和其他 AI ASIC，而非 CPU。[Gartner](https://www.gartner.com/en/newsroom/press-releases/2025-10-15-gartner-says-artificial-intelligence-optimized-iaas-is-poised-to-become-the-next-growth-engine-for-artificial-intelligence-infrastructure)
- McKinsey 预计到 2030 年推理将成为 AI 数据中心的主要工作负载，占 AI 计算一半以上；这是预测，不是已审计的当前事实。[McKinsey](https://www.mckinsey.com/featured-insights/week-in-charts/the-future-of-ai-workloads.)
- Alphabet 和 Microsoft 的 token 数据证明生产调用正在爆发，但训练 token 的一次处理包含反向传播，不能与推理 token 一比一换算 FLOPs。[Alphabet 2025 Q2](https://abc.xyz/investor/events/event-details/2025/2025-Q2-Earnings-Call/)、[Microsoft FY2025 Q3](https://www.microsoft.com/en-us/investor/events/fy-2025/earnings-fy-2025-q3)

### 更准确的投资命题

```
模型训练成本高、次数有限
    → 成功模型被亿万次部署，推理成为持续性运营负载
        → GPU/ASIC 负责矩阵计算与 token 生成
        → CPU 负责请求、编排、检索、数据库、网络、存储和工具执行
            → CPU 绝对需求上升，但 CPU 在整套系统中的价值占比未必上升
```

> **核心判断**：未来三至五年，“单位训练成果被使用更多次”比“CPU 将替代 GPU”更可靠。

## 第二步：CPU 与 GPU 到底各做什么

### 大模型推理的物理结构

| 环节 | 特征 | 更合适的硬件 |
|---|---|---|
| Prompt prefill | 大矩阵乘、计算密集，影响首 token 延迟 | GPU / TPU / ASIC |
| 大模型 decode | 每个 token 反复读权重，低 batch 时受内存带宽限制 | HBM GPU / ASIC |
| API gateway、鉴权、路由、限流 | 分支多、通用逻辑多 | CPU |
| Tokenization、dynamic batching、kernel launch | 加速器前后的控制路径 | CPU |
| RAG 文档解析、检索、过滤、向量数据库 | DRAM、存储、网络与通用计算密集 | CPU 为主 |
| Agent 状态机、工具/API、浏览器、代码执行 | 串行、异构、不可预测 | CPU |
| 小型量化模型、低 QPS、离线任务 | 容量和闲置成本比峰值吞吐重要 | CPU 可胜 |
| 8B+ 低延迟在线、70B+、多模态 | 严格 TTFT/TPOT、高吞吐 | GPU / ASIC |
| 端侧推理 | 功耗、隐私、实时性 | NPU/iGPU 主算，CPU 控制与 fallback |

### 为什么“内存容量大”不等于“推理快”

AMD EPYC 9565 单路 DDR5 峰值带宽约 614 GB/s，而 NVIDIA H200 的 141GB HBM3e 带宽约 4.8 TB/s，后者约为前者的 7.8 倍。CPU 可以用数 TB 的便宜内存装下更大模型，但 decode 必须在每个 token 读取大量权重，带宽通常比“装不装得下”更关键。[AMD EPYC 9565](https://www.amd.com/en/products/processors/server/epyc/9005-series/amd-epyc-9565.html)、[NVIDIA H200](https://www.nvidia.com/en-au/data-center/h200/)

AMD 自己的 CPU/GPU 测试也显示，在特定 BF16 Llama-3.1-70B、32 并发、1024-token prompt 场景中，两张 H100 的 TTFT 约 4 秒，而双路 EPYC 约 76 秒。CPU 在大 batch 聚合吞吐上可以缩小差距，但仍不适合对延迟敏感的大模型在线服务。[AMD CPU/GPU LLM 白皮书](https://www.amd.com/content/dam/amd/en/documents/epyc-technical-docs/white-papers/unlocking-the-power-of-llm-performance-on-epyc.pdf)

历史也提供了反证：Google 早在第一代 TPU 的生产评估中，就发现专用推理 ASIC 相比同期 CPU/GPU 有显著性能和能效优势。推理规模扩大经常把通用 CPU 工作负载推向专用加速器，而不是反过来。[Google TPU 论文](https://research.google/pubs/in-datacenter-performance-analysis-of-a-tensor-processing-unit/)

### CPU 的真实增量在哪里

Agentic AI 一次请求往往是：

```
规划 → 多次模型调用 → 检索 → 工具/API → 代码执行 → 验证 → 再规划
```

模型调用仍消耗 GPU/ASIC，但其周围的检索、沙箱、数据库、状态机、网络、安全和验证由 CPU 承担。AWS 给出的经验起点是：1–8B 量化模型、中等 QPS、可接受 100–500ms 延迟可优先 CPU；8B+ 低延迟在线及 70B+ 通常选择 GPU/Trainium。[AWS EKS CPU Inference and Orchestration](https://docs.aws.amazon.com/eks/latest/best-practices/aiml-cpu-inference.html)

AMD 的 host CPU 测试显示，仅更换加速器服务器的宿主 CPU，在其特定测试中可使 8×MI300 与 8×H100 系统端到端延迟平均改善约 9% 与 8%。这说明 CPU 是系统关键路径，但同时说明 CPU 价值是“让昂贵加速器不空转”，不是接管主要矩阵计算。[AMD Host CPU 白皮书](https://docs.amd.com/api/khub/documents/EF_g2gAbrNuBUFUOCyaIow/content)

> **结论**：推理时代是异构计算时代。CPU 与 GPU 都增长，但 GPU/ASIC 仍获取主要 token 计算价值，CPU 获取控制面和通用计算增量。

## 第三步：瓶颈猎手判断

| 判定标准 | CPU | 结论 |
|---|---|---|
| 供给集中度 | x86 两家，另有 Arm、自研云 CPU、NVIDIA Vera/Grace | 集中但并非单点供应 |
| 扩产周期 | 先进制程、基板与内存可形成 1–2 年约束 | 当前偏紧 |
| 替代难度 | x86 软件兼容有壁垒，但云原生负载可迁移 Arm | 中等 |
| 利用率/供需 | Intel 称服务器 CPU 需求超过供应，AMD 与 Intel 财报均显示高增长 | 短期紧张 |
| 需求增速 | Agent、RAG、host attach 带来双位数增长可能 | 中高 |
| 客户验证周期 | 企业服务器切换通常较慢，云厂商验证能力更强 | 中高 |

**瓶颈评级：B 级，局部 A 级。**

CPU 不是 AI 供应链的首要物理咽喉。更紧的环节仍是 HBM、先进封装、scale-up 网络、电力和高带宽存储。CPU 的短期供给紧张可能带来 ASP 与利润增长，但多架构竞争和专用卸载限制长期定价权。

值得注意的反面变化：

1. continuous batching、PagedAttention、量化、prefix cache、speculative decoding 会降低每 token 所需服务器数量；
2. AWS Graviton、Google Axion、Microsoft Cobalt、NVIDIA Vera/Grace 会截获传统 x86 的增量；
3. DPU/SmartNIC、GPU-CPU 一体化会把网络、存储和安全工作从宿主 CPU 卸载；
4. 推理 ASIC 的单位 token 成本下降可能快于需求增长；
5. CPU 需求增长不代表 AMD、Intel 或 Arm 的利润以相同比例增长。

### AMD：业务第一，价格不合格

**生意本质**：卖高性能 x86 CPU 与 AI 加速器，用 chiplet、先进制程和系统平台帮助云厂商提高每瓦计算密度。

2026 Q1 数据中心收入占总收入约 56%，但公司不拆 EPYC 与 Instinct，不能把 $5.8B 全算作 CPU。Mercury Research 的二次报道显示，AMD 2026 Q1 已取得 33.2% 的 x86 服务器 CPU 出货份额和 46.2% 的收入份额，表明份额与高端 ASP 同时改善。[市场份额报道](https://www.tomshardware.com/pc-components/cpus/amd-reaches-46-percent-of-server-x86-cpu-revenue-intel-still-controls-70-percent-of-the-consumer-pc-market-share)

| 护城河来源 | 评分 | 判断 |
|---|---:|---|
| x86 软件兼容与切换成本 | ★★★★☆ | 企业生态成熟 |
| Zen/EPYC 产品执行 | ★★★★☆ | 过去五年持续抢份额 |
| chiplet 与 TSMC 先进制程协同 | ★★★★☆ | 性能、良率与组合灵活性强 |
| CUDA 对抗能力 | ★★☆☆☆ | ROCm 仍是 GPU 业务核心短板 |
| 客户与供应链控制 | ★★☆☆☆ | 依赖 TSMC、HBM、先进封装和大客户 CapEx |

**最强熊案**：当前约 19.6× PS 和 55× forward PE，不只是定价 EPYC 继续抢 Intel 份额，还定价 AMD 在 GPU/机架系统上明显逼近 NVIDIA。只要 MI450/Helios、毛利率或服务器份额有一个不达预期，就可能出现盈利与估值双杀。

**判断**：四个候选中最值得长期跟踪的直接 CPU 产品公司，但当前只适合观察，不适合价值型核心仓。

### Intel：CPU 最纯，但不是便宜股

**生意本质**：用仍然庞大的 x86 安装基础赚钱，同时用 CPU 现金流补贴一项资本极重、尚未证明外部竞争力的先进代工转型。

Q2 2026 DCAI 收入 $6.262B、同比 +59%，营业利润 $2.474B、利润率约 39.5%，证明服务器 CPU 景气已经进入利润表。与此同时，Intel Foundry 仍亏损 $2.089B；外部 foundry 收入仅 $293M。公司预计服务器 CPU 行业 2026、2027 年均有强劲双位数出货增长，并称需求超过供应。[Intel Q2 2026 CEO/CFO comments](https://download.intel.com/newsroom/2026/earnings/Intel-Q22026-Earnings-Call.pdf)

| 护城河来源 | 评分 | 判断 |
|---|---:|---|
| x86 安装基础、OEM 与企业渠道 | ★★★★☆ | 存量很强，但持续被 AMD/Arm 侵蚀 |
| Xeon 软件兼容 | ★★★★☆ | 迁移成本真实 |
| 先进制造与美国战略价值 | ★★★☆☆ | 战略价值高，商业回报仍待证明 |
| 资本效率 | ★☆☆☆☆ | Foundry 巨额投入和亏损是结构性拖累 |
| 管理层执行 | ★★★☆☆ | 近期改善明显，尚未跨越完整制程周期 |

**最强熊案**：当前约 $433B 市值和约 55× forward PE，已经不是困境反转价格。投资者同时承担 AMD/Arm 份额侵蚀、18A/14A 良率、外部客户、Foundry 资本开支与现金流风险。

**判断**：DCAI 的修复比旧叙事更真实，但整家公司仍是“优质 CPU 分部 + 高风险 foundry”的组合。仅适合作为转型期权，不适合作为 CPU 主题核心仓。

### Arm：最纯的架构税，最差的赔率

**生意本质**：向几乎所有低功耗计算设计收取许可费和 royalty，并尝试从卖 IP 向卖完整 CPU 芯片扩张。

FY2026 收入 $4.920B、同比 +23%，royalty $2.613B、同比 +21%；公司称数据中心 royalty 同比翻倍以上。Arm 还在 2026 年 3 月推出首款自有 AGI CPU，预计相关系统最早 2026 Q4 上市。[Arm AGI CPU](https://newsroom.arm.com/news/arm-agi-cpu-launch)

| 护城河来源 | 评分 | 判断 |
|---|---:|---|
| ISA、开发者与芯片设计生态 | ★★★★★ | 从手机、边缘到云端广泛存在 |
| 功耗效率 | ★★★★☆ | 电力约束下价值上升 |
| royalty 轻资产模型 | ★★★★★ | 增量毛利潜力强 |
| 定价权 | ★★★★☆ | Armv9、CSS 提升每芯片价值 |
| 治理与客户冲突 | ★★☆☆☆ | SoftBank、Arm China、关联交易；自卖芯片可能与授权客户竞合 |

**最强熊案**：约 52.8× PS、接近 300× TTM PE、约 123× forward PE，要求多年高增长、royalty rate 上升和 AGI CPU 成功同时兑现。即使公司判断正确，股票也可能长期回报很差。

**判断**：最能表达“Arm 成为 AI 数据中心 CPU 标准”的公司，但当前是叙事资产，不是有安全边际的投资。

### TSMC：不押架构，谁赢都收费

**生意本质**：为最先进的 CPU、GPU、ASIC 与网络芯片提供难以替代的制造和封装，让客户承担产品路线风险，自己收先进制程税。

Q2 2026 收入 $40.20B、同比 +33.7%，毛利率 67.7%，营业利润率 60.3%，净利率 55.6%；先进节点占晶圆收入 77%。HPC 占收入 66%，但不能把 HPC 全部算成 CPU。[TSMC Q2 2026](https://pr.tsmc.com/japanese/news/3326)

| 护城河来源 | 评分 | 判断 |
|---|---:|---|
| 先进制程、良率和规模 | ★★★★★ | 全球最强、最可验证 |
| 客户信任与中立性 | ★★★★★ | 同时服务互相竞争的设计公司 |
| 先进封装协同 | ★★★★★ | AI 系统瓶颈的重要部分 |
| 资本效率 | ★★★★☆ | 重资产但回报率和利润率优异 |
| 地缘政治 | ★☆☆☆☆ | 低概率、极高损失、难以分散 |

**最强熊案**：公司质量最好，但当前约 28× TTM PE 已明显高于传统半导体周期估值。AI CapEx 放缓、海外厂成本、地缘冲突或客户自建供应链都会压缩估值。

**判断**：并非纯 CPU 标的，却是“推理硬件需求增长”最稳健的架构中立表达。四者中风险调整后最佳，但现价也只能称合理偏贵。

## 第七步：最终决策与行动清单

### 业务排序与股票排序不是一回事

### 空仓者

当前不应因为一句“推理大于训练”就建立 CPU 主题核心仓。更合理的做法是：

1. 把 AMD 设为直接 CPU 首选观察名单；
2. 把 TSMC 作为架构中立的风险调整后首选；
3. Intel 只按转型期权处理；
4. Arm 等待估值大幅压缩；
5. 若真正想表达“推理增长”，组合不能缺少 GPU/ASIC/网络与电力，而不能只买 CPU。

| 类型 | 具体信号 |
|---|---|

### 仓位原则

CPU 不是 AI 供应链的 S 级瓶颈，且当前估值普遍过高。CPU 子主题更适合作为总资产的 2%–4% 研究仓位上限；若已经持有较多 NVIDIA、Broadcom、TSMC 或大型云厂商，需把它们隐含的 CPU/AI 基础设施暴露合并计算，避免重复押注同一 AI CapEx 周期。

## 最终结论

1. **“未来推理大于训练”方向合理，但必须限定口径。** token、调用量和持续运行时长高概率超过训练；FLOPs 可能略占主导；芯片收入与服务器 CapEx 尚无公开证据证明过半。
2. **推理大于训练不等于 CPU 大于 GPU。** 对 8B+ 在线大模型，尤其 70B+、长上下文和高并发，核心 token 计算仍由 GPU/ASIC 主导。
3. **CPU 的真实受益点是系统外围变成核心路径。** Agent、RAG、数据库、检索、工具调用、网络、存储、安全与宿主调度会增加 CPU 需求。
4. **若必须选一个直接 CPU 公司，业务上选 AMD。** 它的份额趋势、产品执行和 CPU+GPU 平台最强，但当前约 20×PS 使股票不具安全边际。
5. **若追求风险调整后胜率，选 TSMC 而非纯 CPU。** 它不押 x86、Arm、GPU 或 ASIC 谁赢，但当前价格也只属合理偏贵。
6. **Intel 是转型期权，Arm 是架构期权。** 两家公司逻辑都可能正确，当前价格却要求过多成功。
7. **当前最好的动作是建立观察名单，不是追高。** 好趋势、好公司和好价格必须同时成立。

> **段永平式追问**：CPU 需求增长当然可能是真的，但如果这个事实所有人都知道，且 AMD、Intel、Arm 已经分别交易在约 20×、8×、53×销售额，买入者究竟赚的是企业成长的钱，还是下一位投资者愿意支付更高倍数的钱？
